# 옮겨

폰·PC·태블릿 사이에서 파일과 글을 원본 그대로 주고받는 웹앱입니다. 기종과 방향에 상관없이 됩니다(아이폰 ↔ 갤럭시, 폰 ↔ PC, PC ↔ PC).

## 실행

```bash
npm install
npm start
```

서버가 켜지면 주소가 두 개 나옵니다.

- `http://localhost:8080`: 이 PC에서 열 때
- `http://192.168.x.x:8080`: 같은 와이파이의 폰이나 다른 PC에서 열 때 (QR에 자동으로 들어갑니다)

처음 실행할 때 Windows 방화벽이 Node.js 허용 여부를 물으면 **개인 네트워크 허용**을 눌러야 폰에서 접속할 수 있습니다.

## 쓰는 법

1. 한 기기에서 **새로 연결하기**를 누르면 QR과 6자리 코드가 나옵니다.
2. 폰은 카메라로 QR을 찍고, PC는 사이트에서 코드를 입력합니다.
3. 파일을 고르거나 끌어다 놓거나 붙여 넣으면 연결된 기기로 넘어갑니다. 글과 링크도 보낼 수 있습니다.
4. PC에서는 **폴더째 보내기**나 폴더 끌어다 놓기로 폴더 구조를 유지한 채 보낼 수 있고, 받는 쪽은 zip 하나로 저장합니다.
5. 전송 중에 연결이 끊기면 멈춤으로 표시되고, 같은 기기가 다시 연결되면 받은 지점부터 이어서 보냅니다.
6. 다음에 사이트를 열면 지난번 연결로 자동으로 다시 들어갑니다.
7. 종 모양 버튼으로 알림을 켜면, 다른 창을 보고 있을 때 받은 파일과 글을 알려 줍니다. 탭 제목에도 "(2) 옮겨"처럼 표시됩니다.
8. 받은 사진·영상의 썸네일을 누르면 크게 보고 좌우로 넘길 수 있습니다.
9. PC(크롬·엣지)에서 **바로 저장할 폴더**를 지정하면 받은 파일을 메모리에 모으지 않고 디스크에 바로 씁니다. 수십 GB도 받을 수 있습니다.

## 연결 보안

- **새 기기 입장 승인:** 방에 이미 기기가 있으면, 새 기기가 코드나 링크로 들어올 때 기존 기기에 "○○가 들어오려고 해요 [허용] [거절]"이 뜹니다. 허용해야만 들어옵니다(2분 안에 답이 없으면 취소). 한 번 허용했거나 같은 방에서 만난 기기는 다음부터 묻지 않고 통과합니다.
- **코드 무작위 대입 막기:** 같은 접속 주소(IP)에서 10분 안에 코드를 10번 틀리면 10분 동안 코드 입장을 막습니다. 링크(QR)로 들어오는 건 막지 않습니다. 회사처럼 여러 사람이 같은 인터넷 주소를 쓰면 함께 막힐 수 있습니다.

## 대화창과 연결별 기록

- 주고받은 파일과 글은 메신저처럼 말풍선으로 쌓입니다(보낸 것은 오른쪽, 받은 것은 왼쪽). 대화창 안에서 스크롤되고, 위로 올려 보는 중에 새 메시지가 오면 "새 메시지 ↓" 버튼이 뜹니다.
- 기록은 **연결(방)마다** 이 브라우저의 IndexedDB에 저장됩니다. 새로 연결하면 빈 대화창에서 시작하고, 메인의 **다시 연결**로 예전 연결에 들어가면 그 연결의 기록이 다시 보입니다.
- 파일 내용은 항목당 200MB까지 보관합니다. 더 큰 파일은 "기록만 남음"으로 표시되고, 바로 저장 폴더에 받은 파일은 그 파일을 가리키는 정보만 저장합니다.
- 기록은 서버에 저장되지 않고 각 기기의 브라우저에만 있습니다.
- 메시지의 **삭제**(두 번 눌러 확인)나 대화창의 **기록 지우기**는 상대 기기에서도 지워집니다. 상대가 지금 연결돼 있지 않으면 "삭제 표시"를 30일 동안 보관했다가 그 연결에서 다시 만날 때 전달합니다. 상대가 이미 다운로드하거나 폴더에 저장한 파일은 지워지지 않습니다.
- 대화창은 최근 100개만 먼저 그리고, "이전 기록 더 보기"로 100개씩 더 불러옵니다. 메인 화면에 이 브라우저가 쓰는 저장 용량을 표시합니다.
- 폴더 동기화, 바로 저장, 알림, 종단간 암호화는 **https 주소나 localhost에서만** 켜집니다. http 주소로 열면 화면 위에 안내가 뜹니다.

## 모임 앨범

- 같은 연결(방)에 들어온 사람 모두 **모임 앨범** 탭에서 사진·영상을 올리면, 사진 속 촬영 시각(EXIF) 기준으로 한 앨범에 합쳐집니다. 폰에서도 됩니다.
- 올릴 때는 작은 미리보기(약 30KB)만 모두에게 보내고, 원본은 필요한 사진만 골라 **원본 받기**로 받습니다. 원본은 올린 사람(또는 이미 원본을 받은 사람)에게서 기기끼리 직접 받습니다. 서버에는 사진을 저장하지 않습니다.
- 나중에 들어온 사람도 기존 사진 목록을 받습니다. 원본은 올린 사람이나 원본을 가진 사람이 연결돼 있을 때 받을 수 있습니다.
- 연사처럼 비슷한 사진(20초 안, 이미지 지문이 비슷함)은 "비슷한 사진 N장"으로 묶습니다.
- 받은 원본은 바로 저장 폴더가 있으면 그 안의 "모임 앨범 날짜" 폴더에, PC는 zip으로, 폰은 공유 메뉴로 저장합니다.
- 내가 올린 사진만 모두의 앨범에서 지울 수 있습니다.

## 오래된 기록 자동 정리

- 사이드바와 메인 화면의 **기록 보관**에서 파일 내용 보관 기간(계속 보관 / 7일 / 30일 / 90일)을 고릅니다. 기본은 계속 보관입니다.
- 기간이 지난 파일은 **내용만** 정리하고 메시지와 파일 이름은 남깁니다. 정리 3일 전부터 파일에 "N일 뒤 내용 정리"가 표시되고, 기간을 바꿔서 바로 정리될 파일이 있으면 먼저 물어봅니다.

## 연결 경로와 TURN (선택)

파일은 가능한 한 빠른 길로 갑니다: **직접 연결 → TURN 중계 → 우리 서버 경유**.

- 직접 연결: 기기끼리 바로 주고받습니다. 같은 공유기 안이면 인터넷에 나가지도 않습니다.
- TURN 중계: 회사 방화벽이나 LTE처럼 직접 연결이 막힌 곳에서, 가까운 전송 전용 중계 서버를 거칩니다. 종단간 암호화된 채로 지나가서 중계 서버도 내용을 볼 수 없습니다.
- 서버 경유: 위 둘이 모두 안 될 때의 대비책입니다. Render 무료 서버를 거쳐서 느리고 무료 대역폭을 씁니다.

TURN은 Render의 Environment에 아래 중 하나를 넣으면 켜집니다(없으면 서버 경유로 넘어감).

| 서비스 | 환경 변수 |
|---|---|
| Cloudflare | `CF_TURN_KEY_ID`, `CF_TURN_API_TOKEN` |
| Metered | `METERED_DOMAIN`(예: `myapp.metered.live`), `METERED_API_KEY` |
| 직접 운영 | `TURN_URLS`(쉼표로 구분), `TURN_USERNAME`, `TURN_CREDENTIAL` |

연결된 기기 옆에 "직접 연결 · 같은 네트워크 / 직접 연결 / 중계 연결 (TURN) / 서버 경유"가 표시됩니다.

**여러 통로로 동시에 보내기**: 직접 연결(또는 TURN)이 되면 연결을 3개 더 열어 총 4개 통로로 조각을 나눠 보냅니다(표시: "통로 4개"). 한 연결 안에서 통로만 늘리면 같은 혼잡 제어를 나눠 써서 빨라지지 않기 때문에 연결 자체를 여러 개 엽니다. 조각마다 순번이 있어 받는 쪽이 순서대로 맞추고, 전송 중 통로 하나가 끊기면 받은 지점부터 이어서 보냅니다. 멀리 떨어진 PC 사이처럼 지연이 큰 경로에서 효과가 크고, 같은 공유기 안에서는 차이가 작습니다. 예전 버전과 연결되면 통로 하나로 보냅니다.

**절전 막기**: 대화 전송·폴더 동기화·앨범 원본 받기 중에는 화면과 PC가 잠들지 않게 하고(위쪽에 "화면 켜 둠" 표시), 끝나면 바로 풉니다. 다른 탭을 보는 동안에도 전송 흐름이 늦어지지 않도록 브라우저가 늦추지 않는 워커 타이머를 쓰고, 받는 쪽은 받는 동안 "살아 있음" 신호를 보내서 큰 파일을 저장하느라 응답이 늦어도 처음부터 다시 보내지 않습니다.

## 폴더 동기화 (PC ↔ PC, 크롬·엣지)

zip으로 묶지 않고 폴더를 통째로 맞춥니다. 처음엔 전부, 그다음부터는 바뀐 파일만 보냅니다.

1. 보내는 PC에서 **공유할 폴더 고르기** → 연결된 PC 옆의 **이 기기와 공유**
2. 받는 PC에서 **받을 위치 고르기** (고른 위치 안에 같은 이름의 폴더를 만들어 받음)
3. 파일이 바뀌면 몇 초 안에 **공유하기** 버튼이 켜집니다. 같으면 "✓ 같아요"로 꺼져 있습니다.
4. **변경 목록 보기**로 추가·수정·삭제된 파일을 보고, 텍스트 파일은 **바뀐 줄**을 GitLab처럼 볼 수 있습니다.
5. **히스토리**에서 지난 동기화 기록과 파일별 바뀐 줄을 다시 볼 수 있습니다(PC마다 최근 200번).

옵션: 바뀌면 자동으로 보내기, .gitignore 규칙 따르기, 내 쪽에 없는 파일은 상대 쪽에서도 지우기(기본 꺼짐), 제외 규칙(.gitignore 문법).

- 고른 폴더와 짝은 브라우저(IndexedDB)에 기억해서 다음 접속 때 다시 고르지 않습니다. 브라우저를 다시 열면 "폴더 접근 허용"을 한 번 누르거나, 크롬에서 "방문할 때마다 허용"을 고르면 됩니다.
- 공유는 기기를 직접 골라야만 시작되고, 받는 쪽이 수락해야만 파일이 쓰입니다.
- 한 방향(보내는 PC → 받는 PC)입니다. 받는 PC에서 고친 파일은 다음 공유 때 덮어씁니다.
- 파일은 다 받은 뒤 한 번에 바뀌므로 쓰는 도중에 깨진 파일이 남지 않습니다.
- 64KB 이하 작은 파일은 최대 1MB·200개씩 **한 묶음으로** 보내서, 작은 파일이 많은 폴더의 첫 동기화가 빨라집니다.
- 코드·문서 같은 **텍스트 파일은 보내는 동안 압축**(gzip)하고 받는 쪽이 받으면서 풀어서 원래 파일로 씁니다. 받는 쪽에는 압축이 풀린 원본이 저장됩니다. 사진·영상·zip처럼 이미 압축된 파일은 그대로 보냅니다.
- 보내기 전에 **예상 시간**(지난번 실제 속도, 처음이면 연결 경로별 기본값)을, 보내는 중에는 실제 속도로 **남은 시간**과 **압축으로 절약한 비율**을 보여 줍니다.
- **동기화 확인** 버튼은 양쪽 폴더를 지금 다시 훑어서 비교하고, 진행 단계(내 폴더 확인 → 상대 폴더 확인)와 결과(양쪽 파일 개수, 마지막 확인 시각)를 보여 줍니다.
- 보내는 중에 새로고침하거나 연결이 끊겨도 다시 연결되면 남은 파일을 자동으로 이어서 보냅니다. 보내는 중에 규칙을 바꾸면 보내기가 끝난 뒤 다시 비교합니다.
- 공유 폴더 설정은 연결(방)마다 따로 저장됩니다.
- **공유 끊기**를 누르면 진행 중인 전송도 바로 멈춥니다.
- 받는 쪽 응답이 30초 동안 없으면 멈춘 것으로 보고, 남은 파일만 최대 3번 자동으로 다시 보냅니다.

## 구조

- `server.js`: 정적 파일 제공, 기기끼리 서로를 찾게 해 주는 중개(WebSocket 시그널링), 직접 연결이 안 될 때 데이터 중계
- `public/app.js`: WebRTC 데이터 채널로 기기끼리 직접 전송합니다. 6초 안에 직접 연결이 안 되면 서버 경유로 자동 전환합니다. 직접 연결이면 연결을 여러 개 열어 조각을 나눠 보내고, 받는 쪽이 순번대로 맞춥니다.
- 받는 쪽은 32MB마다 조각을 Blob으로 묶어서 큰 파일도 메모리를 덜 씁니다.
- **종단간 암호화**: 기기마다 ECDH(P-256) 키를 만들고 상대와 AES-GCM 키를 합의합니다. 서버는 공개키만 전달하므로 직접 연결이든 서버 경유든 내용을 볼 수 없습니다. 양쪽 화면의 보안 코드가 같으면 중간에서 키를 바꿔치기한 사람이 없다는 뜻입니다. HTTPS에서만 켜집니다.
- **이어받기**: 파일마다 고유 id가 있고, 보내기 전에 받는 쪽이 이미 받은 바이트 수를 알려 주면 그 지점부터 보냅니다.
- **폴더**: 받는 쪽이 파일을 받으면서 CRC32를 계산해 두었다가, 저장할 때 비압축 zip으로 묶습니다.
- `public/fsutil.js`: 폴더 접근, 해시 캐시([크기, 수정 시각, 해시]로 바뀐 파일만 다시 계산), .gitignore 문법 제외 규칙, 줄 비교(LCS)
- `public/sync.js`: 폴더 동기화. 받는 쪽이 목록과 해시를 보내면 보내는 쪽이 비교해서 다른 파일만 확인 없이 연달아 보냅니다(확인 안 된 양이 24MB를 넘으면 잠시 멈춤).
- `public/sw.js`: 앱 화면을 캐시해서 서버가 잠들어 있어도 화면이 바로 뜨고 "서버를 깨우는 중" 안내를 보여 줍니다.

## Render 무료 배포

1. 이 폴더를 GitHub 저장소로 올립니다.
2. [Render](https://render.com)에 GitHub 계정으로 가입합니다.
3. **New → Blueprint**를 누르고 저장소를 고르면 `render.yaml` 설정대로 무료 웹 서비스가 만들어집니다.
4. 몇 분 뒤 `https://omgyeo-xxxx.onrender.com` 같은 주소가 생깁니다.

무료 플랜은 15분 동안 접속이 없으면 잠들고, 다음 첫 접속 때 깨어나는 데 30초~1분이 걸립니다. GitHub에 새로 올리면 자동으로 다시 배포됩니다.

## HTTPS (선택)

`cert/key.pem`, `cert/cert.pem`이 있으면 HTTPS로 실행됩니다. HTTP에서는 폰 브라우저가 다음 기능을 막습니다.

- 받은 글 **복사 버튼**: 대신 글을 길게 눌러 복사합니다.
- 아이폰의 **공유 메뉴로 사진 앱에 저장**: 대신 파일 앱의 다운로드 폴더에 저장됩니다.

인터넷에 배포하면(HTTPS 호스팅) 이 제약이 사라지고 같은 와이파이가 아니어도 연결됩니다.

## 알려진 한계

- 전송하는 동안 양쪽 모두 페이지를 열어 두어야 합니다. 아이폰은 다른 앱으로 넘어가면 연결이 끊깁니다.
- 폰 브라우저는 수 GB 파일에서 메모리가 모자랄 수 있습니다.
- 이어받기는 페이지를 새로고침하거나 닫으면 안 됩니다. 받던 내용이 메모리에만 있기 때문입니다.
- 폴더 zip은 4GB 미만만 됩니다. 그보다 크면 파일 각각 저장을 씁니다.
- 폴더 보내기는 PC 브라우저에서만 됩니다(폰 브라우저는 폴더 선택을 지원하지 않음).
- 회사·학교처럼 직접 연결을 막는 네트워크에서 인터넷 배포 버전을 쓰면, 서버 경유 트래픽만큼 서버 대역폭이 듭니다.
